## P0 · 影响正确性或存活

### 1. ~~竖井要**选定一列打通**，不要在多列之间轮换~~ ✅ 已做（目标锁+focus）
- 现象：目标元素（氧石）每轮「最近的那个」都变 → 代理在 123 / 126 / 127 三列之间来回，
  梯子铺了一堆，每列都没挖到顶。
- 代价：梯子材料（约 100kg/格）成倍浪费，节点推进极慢。
- 要点：语义目标一旦选定，就**锁定目标格**（或至少锁定目标列），直到该格被挖开或判定不可达。
- 验收：同一节点连续多轮只在一列上推进。

### 2. ~~调度器的「动作 → 计划节点」匹配表缺出口~~ ✅ 已做（Rescue 扩展+显式报告）
- 现象：有人所在格被判定为 CO₂ → 每轮 Urgent，但救援节点已完成 → 匹配不到任何节点
  → 静默回落到常规计划节点，**紧急态被稀释**。
- 要点：调度指令与计划节点的匹配表要覆盖「CO₂ 环境 / 换气 / 往上挖」等环境类动作，
  匹配不到时**必须显式报告**（而不是无声回落）。
- 验收：日志里 Urgent 与实际执行节点一致；匹配不到时有一行明确说明。

### 3. 「还有活」的可信来源要更全面
- 现象：mod 下发的工单在 step_facts 里**看不见**（地图上有标记，pending_orders = 0），
  现在靠挖掘结果里回报的「视野内还有 N 格待完成」兜底 —— 但那只覆盖当前矩形。
- 风险：矩形外的旧工单会被当成「没活」→ 冻回暂停 → 工单永远不执行。
- 要点：把「在位工单」变成**世界级事实**（例如统计可达区内的标记总数），
  不要依赖单次动作的局部视野。
- 验收：任意时刻都能回答「全局还有几张工单在排队」。

### 5. ~~斜向阶梯会不会产生真空，取决于与前一格是否**正交连通**~~ ✅ 已写进 AGENTS.md 13.41 + 知识库 §9

  → 复制人进去呼吸 0 → 后续工单全阻塞（看起来像没有落脚格）。
  而 Y=202 沿东的同类阶梯，每格与前一格**正交**相邻 → 气体连通 → 无真空 → 正常推进。
- 规则：**往上/往前挖出的格子，必须与已挖空格正交连通**；只有对角连通 = 真空袋 = 死路。
- 配套：预检要把「目标格挖开后是否与可呼吸空间正交连通」纳入判断（真空 = 死亡格）。

### 8. ~~Urgent 分支里 rescue 节点无条件抢占~~ ✅ 已修（V3 移出图；rescue 目标改为高处/富氧区建筑优先）

### 9. ~~survival_node 与节点 rescue 标记语义混用~~ ✅ 已修（rescue 节点移出依赖图；救援动作由 agent 内建逻辑执行）

  **survival_node = 紧急态强制抢占的目标**。两者分离，各司其职。

## P2 · 架构级

### 10. 无人值守时殖民地的「工作窗口」要有人管
- 现象：窗口到期后守护进程按纪律冻回暂停，等待**新的窗口请求** ——
  这一小时里殖民地全程冻着（氧气 213kg、砂岩 5080kg 都在，人却闲着）。
- 现状解法：后台「窗口泵」定时续窗（临时措施）。
- 要点：把「工作节律」做成代理的一等概念（类似紧急态的占空比）：
  有可执行目标时按 **冻 20s → 跑 120s** 的节律自持；
  没有目标、或用户手动暂停时绝不自动恢复。
- ★ 边界：用户手动暂停永远优先；代理自持窗口 ≠ 越权恢复。

### 11. 抢占没有「回切」策略（已评估，暂缓：需改核心循环，刚经历事故8按§13.15克制）
- 现象：调度器 Level≥2 抢占静态计划后，被抢的节点可能长期饿死。
- 要点：给被抢占的节点记一次「被推迟」，恢复后优先回切；连续推迟 N 次就换方案。

### 12. 熔断之后要有「换方案」的自动序列
- 现象：熔断只是把节点标 blocked，等人工或依赖图复活；没有「下一个方案是什么」。
- 要点：给语义节点配**备选序列**（换列 → 换元素 → 换目标类型 → 标记不可达），
  熔断时自动沿序列往下走，而不是停下来等人。

## P0 · 小星局（续）新增条目

### 10. locked_out 的**提前返回**把「横向挖前沿」也一起禁掉（已修）
- 现象：代理每轮日志都是「锁定列没有需要梯子的前沿格 → 本轮不下单」，复制人全空闲。
- 根因：locked_out 的本意是「梯子分支不换列」，代码却直接 return，把**横向分支**也禁掉了。
  而横向分支本身就有 focus 优先级（挖锁定格）→ 根本不会换列。
- 正解：locked_out 只清空梯子候选，**不提前返回**；横向分支照常按 focus 优先级挖。
- 验收：地表节点能连续多轮产出「新标记 1」。

### 11. 1 格宽竖井 = CO₂ 陷阱（已写进知识库 §9）
- 现象：基地是死端气室，CO₂ 沉底；复制人下井作业/睡觉，呼吸 48→36→0。
- 正解：① 居住与作业区搬到上方空腔；② 通风井要 **2 格宽**（两条相邻竖井）才有置换效果；
  ③ 真正的根治是**打通到地表**（永久排气口），否则 CO₂ 只会越积越多。

### 12. 倒地的复制人**搬不动**（待修）
- 现象：dupes_control move_to 报「Duplicant cannot reach target cell」——
  移动需要**寻路**，倒地的走不了；连"恢复呼吸"中的复制人也会失败（目标不在其可达集）。
- 影响：救援机制对"倒地"这一最危险状态实际无效 → 倒地就等于慢慢等死。
- 正解方向：把倒地者**抬到床上**（ONI 的 Rescue chore 需要有床才触发）；
  本局床建在基地 CO₂ 区 = 抬过去也是死路 → 床必须先建在富氧区。

### 13. mod 的 restart_load **只支持 Linux**（已绕过）
- 现象：`oni restart` → restart_relay_unsupported（macOS 上没有 game binary 回退）。
- 正解：用 `game_control domain=save action=load index=<n>` 加载 ONI 自动存档（Cycle N 的 autosave ✓）。
  ⚠ 加载前**先把 autosave 文件复制到别处**（加载过程可能覆盖它）。

### 14. 「铺砖反查植物」会把基地空间铺满（我的失误，已记）
- 现象：为了找到基地里的植株，用「在该格铺一块砖 → 读报错里的 plant prefab」反查，
  结果在空腔里铺了几十块砖 → 2×2 建筑位全被占 → 厕所/床都放不下。
- 正解：反查只用于**只读**判定（临时 blueprint → 读报错 → 立刻取消），
  或直接读 cell 文件（/active/map/cell_X_Y.md 会列出植株 ✓）。
