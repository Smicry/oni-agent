# 快慢系统契约（Fast/Slow Contract）—— 唯一权威

> 本文件定义快系统与慢系统的职责边界。**代码与本文件不一致时，以本文件为准改代码**。
> 背景：此前用 8 处 `escalation_hold` + 4 套冻结机制打补丁，改一处坏一处（紧急闸门挡住保命 goal、
> needs_ai 停手导致厕所建不成、三人空闲）。根因是**同一个"停手"状态被太多主人共享**。本契约废除该模式。

## 1. 一句话分工

- **快系统 = 反射弧**：每 10s 用当前事实做确定性判断 + 安全执行，**永远不停下保命动作**。
- **慢系统 = 战略参谋**：每 5s（+60s 主动规划心跳）依据全局态势给出目标方向与计划，**不审批每一次急症**。

核心原则：**慢系统决定"往哪走"，快系统决定"现在怎么活下来"。慢系统从不阻塞快系统的保命与执行。**

## 2. 不变量（必须恒成立，违反即为 bug）

1. **世界默认运行**：AI 开启时世界应在绝大多数时间运行。暂停只允许三种：
   - hold（用户关 AI 总开关）→ 全场冻结，只有 release 解除；
   - 紧急态占空比（有人倒地/窒息红线）→ 冻 20s 跑 120s；
   - 施工窗口正常到期 → 冻 20s 后自持续窗（有活就续）。
   **"等慢系统"不再是一种暂停理由。**
2. **保命动作不可阻塞**：任何情况下，快系统每轮都必须执行可用的保命动作
   （救援、建厕所、产氧、换气、清污染水）。慢系统是否 resolve、escalation 是否 pending、
   紧急闸门、goal 类型——**一律不得阻止保命动作的执行**。
3. **急症不等 AI**：快系统检测到的 Urgent（呼吸<50、膀胱>80% 且厕所不足、氧气<3周期、
   倒地、stress 飙升）由快系统自己抢占执行；同时上报慢系统做战略参考（可选），
   但**上报不构成等待**。
4. **长线让位急症，但不让位自己**：只有"扩张类"目标（expand/scout/surface/open_chamber）
   在急症时可本轮跳过；"保命/续航类"目标（material/oxygen/element:X/建厕所/制氧/进食）
   任何时候都照常执行。
5. **单一停手源**：不存在全局 `escalation_hold`。若某轮确实要跳过非保命工作，用局部布尔
   （本轮 `can_execute_non_vital = false`），生命周期仅本轮，不跨轮、不共享。
6. **效果可验证**：下了工单不等于生效；每轮复核上轮动作的环境效果，无效则换方案
   （AGENTS.md §9）。反复对同一格下同一工单 ≥3 轮 = 卡住，升级慢系统。

## 3. 快系统每轮的固定流程（顺序即优先级）

```
1. 采快照 + 官方事实校验（读不到 ≠ 极值；人口0 先确认数据源）
2. 运行状态机：世界在不在跑？→ 决定 can_execute（唯一与"运行"相关的闸门）
3. 保命层（每轮必做，不受任何停手影响）：
   a. 复核上轮移动/工单是否生效
   b. 倒地救援（move_to 到安全建筑旁）
   c. priority::direct 算 directive；若 Urgent → 抢占 plan 节点执行
4. 目标层（仅当 can_execute 且无 Urgent 抢占）：消费 ai_goals.jsonl，
   急症时只跳过扩张类 goal（不变量 4）
5. 维护层（有空做）：打印舱奖励、侦察、plan 进度刷新
6. 执行后判空闲/续窗；写决策回执
```

## 4. 慢系统的产出与边界

- **产出**：`ai_goals.jsonl`（语义目标）+ locked `plan.json`（战略节点）+ decisions.jsonl（留痕）。
- **不产出**：不直接暂停世界、不阻断快系统、不做坐标级工单（坐标由快系统算）。
- **反馈**：escalation 带 category 静默去重；resolve note 回灌对话流供下轮推理。
- **终局**：检测人口0 → 产出 rollback 元决策并停止决策（不空转）。

## 5. 状态编码（取代 escalation_hold）

| 状态 | 存储 | 生命周期 | 谁能改 |
|---|---|---|---|
| AI 开关 | hold 文件 + control owner=Hold | 跨重启 | 用户（Web 总开关）/主 agent |
| 紧急占空比 | Agent.danger_cycle + window_until | 本进程 | 快系统（按红线自动） |
| 施工窗口 | window_until + auto_rhythm | 本进程 | 快系统（到期/续窗） |
| 本轮急症跳过扩张 | 局部变量 | **仅本轮** | 快系统（按 directive） |

**没有第五种状态。** 任何"因为慢系统所以停手"的代码都是错误实现。

## 6. 验收标准

- 三人膀胱 100%、厕所 0 时：快系统在 N 轮内建成厕所（N≤5），期间 goal 不被全部跳过；
- 急症发生时：本轮 cycle 日志出现抢占动作，且没有"等慢系统不下工单"；
- 慢系统 resolve 前后：快系统的保命动作序列不变；
- 无 escalation、无用户指令时：60s 心跳仍能产出 goal 并被消费（世界不空转）。
