# 快慢系统契约（Fast/Slow Contract）—— 唯一权威

> 本文件定义快系统与慢系统的职责边界。**代码与本文件不一致时，以本文件为准改代码**。
> 架构总纲（为什么这样分层、v3 迁移路径）见 [`architecture-v3.md`](architecture-v3.md)。
> 背景：此前用 8 处 `escalation_hold` + 4 套冻结机制打补丁，改一处坏一处（紧急闸门挡住保命 goal、
> needs_ai 停手导致厕所建不成、三人空闲）。根因是**同一个"停手"状态被太多主人共享**。本契约废除该模式。

## 1. 一句话分工

- **快系统 = 反射弧**：每 10s 用当前事实做确定性判断 + 安全执行，**永远不停下保命动作**。
- **慢系统 = 战略参谋**：每 5s（+60s 主动规划心跳）依据全局态势给出目标方向与计划，**不审批每一次急症**。

核心原则：**慢系统决定"往哪走"，快系统决定"现在怎么活下来"。慢系统从不阻塞快系统的保命与执行。**

## 2. 不变量（必须恒成立，违反即为 bug）

1. **世界默认运行**：AI 开启时世界应在绝大多数时间运行。暂停只允许以下几种情形：
   - hold（用户关 AI 总开关）→ 全场冻结，只有 release 解除；
   - 紧急态占空比（有人倒地/窒息红线）→ 冻 20s 跑 120s；
   - 施工窗口正常到期 → 冻 20s 后自持续窗（有活就续）；
   - 本轮动作失败但慢系统仍有待办目标（ai_goals_pending / 升级请求）→ 同样冻 20s 后
     自持续窗重试，由熔断计数驱动换目标；
   - **动作失败且慢系统彻底无待办** → 冻回等人工/主 agent 介入（**不自持**）。
     这是终态：世界停着等人决策，不是循环。
     （反例已实测：失败冻回无视 ai_goal → 快系统只观察、慢系统空转入队，互等死锁。）
   **"等慢系统"不再是一种暂停理由。**
   ★ 判定"世界在不在跑"必须用**实时真值**（`isPaused` / `gameSpeed<=0` / 实时复核），
     不能只信批量采集的快照 `paused` —— 用过期值判定会让代理在游戏停着时继续下工单，
     绕过下面第 6 条的"效果可验证"，并触发误熔断（见 AGENTS.md §7.1）。
2. **保命动作不可阻塞**：任何情况下，快系统每轮都必须执行可用的保命动作
   （救援、建厕所、产氧、换气、清污染水）。慢系统是否 resolve、escalation 是否 pending、
   紧急闸门、goal 类型——**一律不得阻止保命动作的执行**。
3. **急症不等 AI**：快系统检测到的 Urgent（呼吸<50、膀胱>80% 且厕所不足、氧气<3周期、
   倒地、stress 飙升）由快系统自己抢占执行；同时上报慢系统做战略参考（可选），
   但**上报不构成等待**。
4. **长线让位急症，但不让位自己**：只有"扩张类"目标（expand/scout/surface/open_chamber）
   在急症时可本轮跳过；"保命/续航类"目标（material/oxygen/element:X/建厕所/制氧/进食）
   任何时候都照常执行。
5. **单一停手源**：不存在全局 `escalation_hold`。若某轮确实要跳过非保命工作，用局部布尔
   （本轮 `can_execute_non_vital = false`），生命周期仅本轮，不跨轮、不共享。
6. **效果可验证**：下了工单不等于生效；每轮复核上轮动作的环境效果，无效则换方案
   （AGENTS.md §9）。反复对同一格下同一工单 ≥3 轮 = 卡住，升级慢系统。
7. **done 必须有证据**：依赖图里 status=done 的节点，每轮要用**同一套判据复核**；
   判据当前不成立 → 打回 todo。done 只代表"曾经达成过"，不代表"现在还成立"。
   （实测本局：E1「地表换气」done 但可达上界只有 194（判据要 216）、
   B1「床位」done 但 beds=0 —— 依赖图以为"换气与床位都完成"，
   于是再没有任何节点要求产氧 → 基地慢慢耗尽。）
8. **不许饿死**：一个节点连续 N 轮"做了但没达成"（stall）就必须**让位**给别的
   ready 节点；选点排序里 stall 的权重高于 unlocks 数量。
   （实测本局：AIR 每轮都能下几格挖掘工单 → 永远压住 P1 供电
   → P1 被选中 **0 次** → 氧气扩散器建成了但没电 → 一点氧都不产 → 全灭。）
9. **造出来 ≠ 在运转**：设备类节点的判据必须包含**运转条件**（通电/有燃料/有水），
   不能只数建筑数量。产氧判据 = 产氧设备在运转（consumerOperational>0 且有发电机），
   不是 prefab_min。
10. **依赖顺序要跟物理顺序一致**：耗电设备的生产节点必须**排在供电节点之后**。
    先造产氧机再供电 = 造一堆废铁。
11. **失败必须诚实上报**（2026-11-23 实测事故）：动作汇总的 `ok` 必须由各结果真实聚合
    （任一失败 → 整体失败），**不能硬编码成功**。零进展（无可下单曲 / 推不动）算**失败**，
    不是成功——否则熔断统计永远读到"成功"→ 连续失败计数不增长 → 熔断永不触发 →
    慢系统无限重复入队推不动的目标 → 快系统恢复→失败→冻回无限乒乓（游戏永远停着）。
    ★ 保命节点**禁熔断**（熔断=永久自杀）但**连续失败要暂缓**（deferred，可恢复）：
    禁熔断 ≠ 每轮都重试，只"本轮停手"会被下一轮重新选中。

## 3. 快系统每轮的固定流程（顺序即优先级）

```
1. 采快照 + 官方事实校验（读不到 ≠ 极值；人口0 先确认数据源）
2. 运行状态机：世界在不在跑？→ 决定 can_execute（唯一与"运行"相关的闸门）
3. 保命层（每轮必做，不受任何停手影响）：
   a. 复核上轮移动/工单是否生效
   b. 倒地救援（move_to 到安全建筑旁）
   c. priority::direct 算 directive；若 Urgent → 抢占 plan 节点执行
4. 目标层（仅当 can_execute 且无 Urgent 抢占）：消费 ai_goals.jsonl，
   急症时只跳过扩张类 goal（不变量 4）
5. 维护层（有空做）：打印舱奖励、侦察、plan 进度刷新
6. 执行后判空闲/续窗；写决策回执
```

## 4. 慢系统的产出与边界

- **产出**：`ai_goals.jsonl`（语义目标）+ locked `plan.json`（战略节点）+ decisions.jsonl（留痕）。
- **不产出**：不直接暂停世界、不阻断快系统、不做坐标级工单（坐标由快系统算）。
- **反馈**：escalation 带 category 静默去重；resolve note 回灌对话流供下轮推理。
- **终局**：检测人口0 → 产出 rollback 元决策并停止决策（不空转）。
- **开局规划（§4.7）**：每局的战略由 LLM 依据**本局世界事实**生成，不是硬编码 playbook。

## 4.7 开局规划（LLM 生成，无本地兜底）

无本地兜底（用户决策：硬编码 playbook 换地图就不适用，已删除）：
1. **快系统**：计划 author ≠ ai 时，采集本局世界事实写 `opening_brief.json`
   （侦察 + 结构化 facts——session 在快系统，只采事实）。
2. **慢系统 LLM 规划**（author=ai，名副其实）：依据 brief 生成节点图 →
   `opening::validate_plan` 强校验 → 落盘。
3. **失败即空窗重试**：LLM 失败/校验不过 → 本轮无战略计划
   （快系统保命层照常跑）→ 冷却 10 分钟后重试；失败原因记 decisions.jsonl。
   通用性来自 prompt 只含**跨局通用原则**（常量 UNIVERSAL_PRINCIPLES）+ 本局事实；
   节点结构由 LLM 依事实决定（水世界→藻类箱/电解器，陆地→氧石扩散器/挖掘换气）。

通用性关键：prompt 只放**跨局通用原则**（厕所前置/材料先行/换气判据用真实可达上界/
缺料自举/造出来≠在运转/产氧需电/研究站解锁高级产氧）+ **本局事实**；
节点结构由 LLM 依据事实决定（水世界→藻类箱/电解器，陆地→氧石扩散器/挖掘换气）。

校验（`opening::validate_plan`）拦截 LLM 幻觉：
判据 kind 白名单 / 判据不得重复 / requires-unlocks 引用存在 / 不得写死坐标 /
**五条生命线必须覆盖**（卫生/氧气/食物/床位/电力）/
**产氧节点的 requires 必须含供电节点**（先电后氧，实测造出来没电=白建）。

失败冷却：失败后 **10 分钟**内不重试（`opening_state.json` 的 `last_fail_ts`，代码值 600s）。
冷却期间 **plan 保持空占位**（`author=pending_llm`，0 节点）——机械 planner 与模板 playbook 已删除，
**没有"模板基线"可执行**。快系统保命层照常跑（保命反射弧不依赖 plan），
慢系统在冷却结束后重新触发开局规划。

## 4.5 循环即升级（执行层死循环的处置）

代码逻辑无法穷举所有情况，硬编码的判据会自我循环（实测：厕所每轮挖同一格 (115,194)，
而那格早已挖开 → 无限循环，厕所永远建不成）。因此**执行层的循环不靠穷举挡住，而是检测出来交给慢系统**：

- 快系统给每个动作算**指纹**（`kind@x,y`，如 `dig@115,194`），维护连续计数；
- 同一指纹连续出现 ≥3 次 → 判定**执行层循环** →
  ① 以结构化卡点上报慢系统（指纹、次数、失败类别 fail_kind、现场事实）；
  ② **暂缓该节点**（下一轮不再选它）→ 打断循环，等慢系统给新方向；
- 指纹中断（换动作）→ 计数归零。

分工不变：**事实与判定归代码，权衡与换路归慢系统。** 代码负责"我发现自己在原地打转"，
慢系统负责"该往哪走"。

## 4.6 判据参数化（让慢系统真正拥有策略权）

"什么算安全落点"这类**权衡**不该硬编码在代码里——硬编码必然在遇到新地图/新局面时
失效（实测：开局氧气稀薄 → "厕所必须纯氧"把落点全否 → 反复挖同一格）。

做法：把判据变成**可执行参数**，由慢系统按局面调整：

```
site_policy.json（按存档）
  co2_max_kg        选址允许的 CO₂ 浓度上限（kg/格）
  strict_prefabs    这些建筑仍要求纯氧（床/发电机/电解器…）
  relax_after_fail  连续失败几次后快系统自动放宽
```

- **快系统**：每轮读当前策略执行选址；连续失败 ≥ relax_after_fail → 自动放宽一档（自愈闭环）。
- **慢系统**：prompt 里看得见当前策略（可调项一目了然）；决策可带 `policy` 字段直接改
  （落盘 + 立即生效，跨进程保持）；也可走 `oni policy set`。
- **边界**：参数只调"阈值与名单"，**不改事实查询**（格子是什么、工单成没成永远由代码查）。

配套的 MCP 优化（让上述闭环跑得动）：同 URI 并发读 **singleflight** 合并；只读缓存
TTL 2s→8s（覆盖一轮 cycle 的多阶段重复读）；web 端口绑定失败自动重试（避免重启后控制台失联）。
★ **关键状态用 per-URI 更短 TTL**：`oni://colony/status`（世界运行/暂停）走 **1s**，
  其余观察源 8s。**不绕过缓存**——同一套 singleflight 合并并发读，
  既保证判定时读到真值（1s ≪ 10s 轮询），又不会打爆 mod 端点。

## 5. 状态编码（取代 escalation_hold）

| 状态 | 存储 | 生命周期 | 谁能改 |
|---|---|---|---|
| AI 开关 | hold 文件 + control owner=Hold | 跨重启 | 用户（Web 总开关）/主 agent |
| 紧急占空比 | Agent.danger_cycle + window_until | 本进程 | 快系统（按红线自动） |
| 施工窗口 | window_until + auto_rhythm | 本进程 | 快系统（到期/续窗） |
| 本轮急症跳过扩张 | 局部变量 | **仅本轮** | 快系统（按 directive） |

**没有第五种状态。** 任何"因为慢系统所以停手"的代码都是错误实现。

## 6. 验收标准

- 三人膀胱 100%、厕所 0 时：快系统在 N 轮内建成厕所（N≤5），期间 goal 不被全部跳过；
- 急症发生时：本轮 cycle 日志出现抢占动作，且没有"等慢系统不下工单"；
- 慢系统 resolve 前后：快系统的保命动作序列不变；
- 无 escalation、无用户指令时：60s 心跳仍能产出 goal 并被消费（世界不空转）。
