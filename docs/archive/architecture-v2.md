# 通用《缺氧》助手 · 架构设计 v2（2026-11-22 小星局复盘后）

> 起因：小星局（3 人开局 → 全灭）暴露出的不是"某个 bug"，而是**三个结构性断点**。
> 本文给出判断与新架构，并明确"**不依赖 AI 在线管控**"要怎么做到。
>
> ★ **文档状态（2026-11-23 更新）**：本文是 2026-11-22 小星局复盘后的**设计方案**。
> 其中的**规划层主线（规则驱动的自动规划器 / 地形特征→策略族 / 事件驱动重规划）已被
> 2026-11-23 的"去 playbook 化"重构推翻**。现行机制见本文 §2/§3/§4 与
> [`FAST_SLOW_CONTRACT.md`](FAST_SLOW_CONTRACT.md) §4.7；
> **§8 与 §10 是历史记录，不是现状**。

## 0. 一句话结论

**架构分层是对的，但"规划层"目前是人工的（由 AI 手写 plan.json），而"世界模型"用的是官方局部数据。**
⇒ 换存档就废（跨局污染）、预检就不可靠（本局 8 个 P0 全部由此派生）。
⇒ 要做的不是"把执行策略调得更细"，而是：
**① 规划层自动化 ② 世界模型自建 ③ 安全护栏前置 ④ 周期内按事件重规划。**

★ **现状（2026-11-23）**：① 已落地为 **LLM 依本局事实生成开局战略**（不再是规则表）；
②③ 已落地；④ 改为 **60s 主动规划心跳 + escalation 驱动**（没有独立的事件重规划判定函数）。

## 1. 本局总结（小星 / 特拉星）

| 阶段 | 结果 | 教训 |
|---|---|---|
| 接手 | plan.json 是上一局残留（全 done）→ 代理空转 40 分钟 | 规划层必须自动生成 |
| 开局 | 复制人被封在 Y=189 一行走廊（官方可达集只有 12 格） | 先看可达集，再决定怎么挖 |
| 中期 | 竖井打通 ✓、发电机 400W ✓、找到 5 株米虱木（食物闭环 ✓） | 斜向阶梯会造真空袋；垂直+梯子才对 |
| 后期 | **三次全员倒地、两次死亡**（Cycle 8 全灭） | 死因不是"某个人不小心"，是**规则漏判** |

**死因链（最终版）**

    代理把「挖掘工位 / 居住落点」落在 CO₂ 主导的格子（0.25~1.4 kg/格）
      → 人慢慢掉呼吸（不是一次致命）→ 倒地
      → move_to 需要寻路、倒地的走不动 → 无人能救 → 全灭

**本局共修 8 个 P0，全部属于同一类错误：**
> **"我以为的"与"游戏的真值"不一致，且系统选择了乐观的一侧。**

| # | 断点 | 乐观假设 | 真相 |
|---|---|---|---|
| 1 | 官方可达集 | 当作全局可达集 | 是 **radius=8/16 的局部窗口 + 12 个稀疏样本** |
| 2 | 建筑索引解析 | 取 cols[3] 是坐标 | cols[3] 是 **ID**，坐标在 cols[4] → 一栋建筑都没标记 |
| 3 | 全图加载 | 与视野模式一致 | 漏标建筑 → 同一张图两种模式结论相反 |
| 4 | 危险判据 | CO₂ > 5kg/格 才致命 | 致命与否看**有没有氧**，0.25kg 的纯 CO₂ 一样致命 |
| 5 | 落脚点判定 | 看复制人当前格危不危险 | 该看**落脚点本身**能不能呼吸 |
| 6 | 救援 | mod 回 ok = 人到了 | ok = **工单已下达**；倒地的执行不了 |
| 7 | 倒地质检 | 继续施工 | 有人倒地必须**全面停工**（但保命节点除外） |
| 8 | 选材 | 目录顺序 = 可用 | 目录第一个材料可能地上 **0kg** |

## 2. 架构判断：骨架不用改，三个断点必须换掉

现有分层（都在，职责清楚）：

    sense.rs 感知 → world/ 世界模型 → decide.rs 选目标 → priority.rs 调度
                 → autoact/exec 执行 → preflight 安全

    规划层 = opening.rs（慢系统 LLM 写 plan.json）→ decide.rs 按依赖图选本轮唯一目标

**断点 A：规划层是人工的。**
plan.json 由 AI 手写 → 换存档全废 → 这就是跨局污染的根源，也是"通用助手"的第一道墙。
→ **要换成自动生成依赖图的规划层**（读世界状态 → 生成依赖图）。

★ 落地形态（2026-11-23 现状）：不是"规则驱动的自动规划器"，而是
**LLM 依本局事实生成**（`opening.rs`）：快系统采本局事实写 `opening_brief.json`
→ 慢系统 LLM 出节点图 → `validate_plan` 强校验 → 落盘 `author=ai, locked=true`。
**无本地兜底**：LLM 失败即本轮无战略计划（空窗，冷却 10 分钟后重试），
快系统保命层照常跑。详见 §4 与契约 §4.7。

**断点 B：世界模型信任官方局部数据。**
官方可达集是局部窗口 + 稀疏样本，而**几乎所有"人能不能到"的判断都建立在它上面**
（预检落脚点、梯子列基座、建造落点）→ 本局 8 个 P0 里有 6 个由此派生。
→ **要自建全局可达图**：全图网格 + ONI 移动规则（水平 / 向下 / 梯子向上 / 斜向台阶）做 BFS，
  官方数据只用来交叉验证。

**断点 C：安全护栏在"下单前"，且用的是同一个不可靠模型。**
护栏失效 = 人死。→ **护栏必须前置**：目标格 / 落脚点 / 居住点 / 工位用**同一把"可呼吸"尺子**；
  且执行后要**复核**（"已下令" ≠ "已生效"）。

## 4. 通用性从哪来：**跨局原则（固定）+ 本局事实（每局不同）**

**关键认知（仍然成立）：ONI 的死因只有 5 类** —— 窒息、污染（脏水/毒气）、饥饿、脱水、过热。
所以通用助手不需要"创造力"，只需要**把这 5 类变成可检测、可拦截的规则**。
这部分由快系统的保命反射弧与安全护栏承担，**与规划层无关**。

**规划层的通用性从哪来（2026-11-23 改）**：

| 曾经的做法 | 问题 | 现在的做法 |
|---|---|---|
| 规则匹配器：地形特征 → 策略族 → 依赖图 | 特征表是硬编码的，换一颗星球就可能匹配错；也没有任何本局事实校验 | prompt 只含**跨局通用原则**（`UNIVERSAL_PRINCIPLES`）+ **本局结构化事实** |
| 模板 playbook（固定节点图） | 水世界 / 金属星 / 沼泽套同一张图必然荒谬 | 节点结构由 **LLM 依事实决定**（水世界→藻类箱/电解器，陆地→氧石扩散器/挖掘换气） |
| 机械 planner 当兜底 | 兜底本身就是"另一张硬编码图"，不如没有 | **无本地兜底**：LLM 失败即空窗（冷却 10 分钟重试），快系统保命层不受影响 |

**同一份通用原则 + 不同的事实 → LLM 排出不同的节点图**，这才是"面对不同情况"。
例：同一局里"零建材开局"与"开局即有建材"得到不同的第一目标；
"水世界"与"金属星"的产氧/供电链顺序也不同。

**幻觉闸门**（`opening::validate_plan` 强校验，不通过不落盘）：
判据 kind 白名单 / 判据不得重复 / requires-unlocks 引用存在 / 不得写死坐标 /
**五条生命线必须覆盖**（卫生/氧气/食物/床位/电力）/
**产氧节点的 requires 必须含供电节点**（先电后氧，实测造出来没电 = 白建）。

★ 结论：**通用性 = 跨局原则（固定） + 本局事实（每局不同） + 强校验（拦截幻觉）**，
而不是"把某张地图的开局套路固化进模板/代码"。

## 5. "每局一个规划 + 每周期实时调整"——对，但两者都要**自动化**

* **每局规划**（开局一次）：生成**目标序列 + 判据 + 动作**，不是坐标清单。
  坐标由世界模型运行时算（这正是 AGENTS.md §8「计划文件不放硬编码坐标」写下的原则）。
  现由慢系统 LLM 依本局事实生成（§4）。
* **每周期调整**（已有 priority.rs）：实时状态 → 指令，能抢占静态计划。
  本局教训：**调度器必须把"人当下在哪、能不能到那"当输入**，否则会把人送进毒气区。

**重规划触发事件**（本局全部踩到）：
人口下降 / 氧气续航 < 阈值 / 某节点连续失败 / 气室结构改变（打通或封闭）/ 资源耗尽。

★ 落地形态（2026-11-23）：**没有独立的事件驱动重规划函数**，改由两条通路实现——
① 慢系统 **60s 主动规划心跳**（无事件时也照常出目标）；
② 快系统检测到卡住 → 写 escalation + **暂缓该节点（deferred）**，等慢系统给新方向。

## 8. 已落地验证（2026-11-22 11:29，**历史记录**）

> ★ **本节是历史记录，不是现状**：当时的机械规划器与开局特征规则表已被 2026-11-23 的
> "去 playbook 化"重构删除（见 §4）。保留本节，是因为它证明了
> **世界模型 + 运行时降级 + 自举**这三件事本身有效——它们与规划层无关，今天仍然成立。

**新存档「陨石坑 / 埃莉星」上跑通完整闭环**（与上一局完全不同的星球与开局）：

```
（当时的机械规划器，已删除）→ 识别开局零建材 → 第一目标 = 采建材
                              （梯子/砖/厕所/床全都造不了 → 先横向采）
代理第 1 轮                  →  「铺梯子缺建材 → 改走横向挖掘」（降级正确）
代理第 2 轮                  →  横向挖到 500kg 砂岩
代理第 3 轮                  →  「竖井：先在 (125,187) 铺梯子，再挖 (125,189) 的头顶」
```

**这就是「不接 AI 在线管控也能玩」的最小闭环**：
开局事实 → 依赖图 → 语义动作 → 运行时降级 → 逐轮推进。

### 通用性证据

| 维度 | 小星局（特拉星） | 陨石坑局（埃莉星） |
|---|---|---|
| 存档指纹 | f9deadc6bcc3006c | 7fc8e406e822936d（互不污染 ✅） |
| 特征 | 1 格高走廊 + 有建材 | 1 格高走廊 + **零建材** + 氢气/氯气 |
| 当时的规则匹配结果 | 憋死型 | **先建材型**（规则自动区分 ✅） |
| 第一目标 | 开竖井 | 采建材 → 再开竖井 |

### 仍然欠账（诚实清单）

* S1 未完成：**全局可达图**仍是「网格BFS ∩ 官方窗口」的混合体，
  官方 samples 的稀疏性仍会影响少数判定（已用网格 BFS 兜住，但不够纯）。
* S3 只做了一半：护栏前置做了（工位/落脚点/居住点同尺子），
  **执行后复核**（人真的到新位置了吗）还没有自动化验证。
* S5 走的是另一条路：**事件驱动重规划**（当时的判定函数 + 接进主循环）**没有保留**；
  现行机制是 60s 主动规划心跳 + 快系统卡住时暂缓节点 + escalation 交给慢系统。
* 开局差异**不再以规则表维护**：极端局（开局就有大量水/毒气）由 LLM 依事实处理，
  校验不通过就不落盘。

## 9. 一句话

> **把「这一局怎么玩」从人的临场判断，变成「LLM 依本局事实生成依赖图」；
> 把「人会不会死」从代理的乐观假设，变成世界模型里可验证的事实。**

剩下的工作不是"更聪明"，而是"更严谨"：
每个"我以为"都要换成"游戏说的"，每个"看起来安全"都要换成"可验证安全"。

### 当前局（陨石坑/埃莉星）实测

```
[自举] 氧气扩散器 造不了 → 去挖 IronOre     ← 产氧缺原料，自动去挖
✅ dig → 前沿 6 格（新 6 / 已有标记 0），本轮挖 1 格：新标记 1
→ 标记落在 (151,193) 的铜矿（基地西侧空腔，最近最上方）
✓ 三人呼吸 100 / 压力 0 / 氧气 397→407kg 上升 / 每轮稳定推进
✓ 开局目标随事实调整：先采建材 →（采到砂岩）→ 转竖井
```

### 仍然欠账

* **长竖井的梯子链**仍是瓶颈："目标列走不通"时只能横向挖，代理不会自己铺一条长梯子链。
* "节点连续失败"触发的重规划**没有实现**：现行处置是**暂缓该节点（deferred）+ 写 escalation**，
