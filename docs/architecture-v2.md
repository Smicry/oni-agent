# 通用《缺氧》助手 · 架构设计 v2（2026-11-22 小星局复盘后）

> 起因：小星局（3 人开局 → 全灭）暴露出的不是"某个 bug"，而是**三个结构性断点**。
> 本文给出判断与新架构，并明确"**不依赖 AI 在线管控**"要怎么做到。

---

## 0. 一句话结论

**架构分层是对的，但"规划层"目前是人工的（由 AI 手写 plan.json），而"世界模型"用的是官方局部数据。**
⇒ 换存档就废（跨局污染）、预检就不可靠（本局 8 个 P0 全部由此派生）。
⇒ 要做的不是"把执行策略调得更细"，而是：
**① 规划层自动化 ② 世界模型自建 ③ 安全护栏前置 ④ 周期内按事件重规划。**

---

## 1. 本局总结（小星 / 特拉星）

| 阶段 | 结果 | 教训 |
|---|---|---|
| 接手 | plan.json 是上一局残留（全 done）→ 代理空转 40 分钟 | 规划层必须自动生成 |
| 开局 | 复制人被封在 Y=189 一行走廊（官方可达集只有 12 格） | 先看可达集，再决定怎么挖 |
| 中期 | 竖井打通 ✓、发电机 400W ✓、找到 5 株米虱木（食物闭环 ✓） | 斜向阶梯会造真空袋；垂直+梯子才对 |
| 后期 | **三次全员倒地、两次死亡**（Cycle 8 全灭） | 死因不是"某个人不小心"，是**规则漏判** |

**死因链（最终版）**

    代理把「挖掘工位 / 居住落点」落在 CO₂ 主导的格子（0.25~1.4 kg/格）
      → 人慢慢掉呼吸（不是一次致命）→ 倒地
      → move_to 需要寻路、倒地的走不动 → 无人能救 → 全灭

**本局共修 8 个 P0，全部属于同一类错误：**
> **"我以为的"与"游戏的真值"不一致，且系统选择了乐观的一侧。**

| # | 断点 | 乐观假设 | 真相 |
|---|---|---|---|
| 1 | 官方可达集 | 当作全局可达集 | 是 **radius=8/16 的局部窗口 + 12 个稀疏样本** |
| 2 | 建筑索引解析 | 取 cols[3] 是坐标 | cols[3] 是 **ID**，坐标在 cols[4] → 一栋建筑都没标记 |
| 3 | 全图加载 | 与视野模式一致 | 漏标建筑 → 同一张图两种模式结论相反 |
| 4 | 危险判据 | CO₂ > 5kg/格 才致命 | 致命与否看**有没有氧**，0.25kg 的纯 CO₂ 一样致命 |
| 5 | 落脚点判定 | 看复制人当前格危不危险 | 该看**落脚点本身**能不能呼吸 |
| 6 | 救援 | mod 回 ok = 人到了 | ok = **工单已下达**；倒地的执行不了 |
| 7 | 倒地质检 | 继续施工 | 有人倒地必须**全面停工**（但保命节点除外） |
| 8 | 选材 | 目录顺序 = 可用 | 目录第一个材料可能地上 **0kg** |

## 2. 架构判断：骨架不用改，三个断点必须换掉

现有六层（都在，职责清楚）：

    sense.rs 感知 → world/ 世界模型 → decide.rs 规划 → priority.rs 调度
                 → autoact/exec 执行 → preflight 安全

**断点 A：规划层是人工的。**
plan.json 由 AI 手写 → 换存档全废 → 这就是跨局污染的根源，也是"通用助手"的第一道墙。
→ **要换成规则驱动的自动规划器**（读世界状态 → 生成依赖图）。

**断点 B：世界模型信任官方局部数据。**
官方可达集是局部窗口 + 稀疏样本，而**几乎所有"人能不能到"的判断都建立在它上面**
（预检落脚点、梯子列基座、建造落点）→ 本局 8 个 P0 里有 6 个由此派生。
→ **要自建全局可达图**：全图网格 + ONI 移动规则（水平 / 向下 / 梯子向上 / 斜向台阶）做 BFS，
  官方数据只用来交叉验证。

**断点 C：安全护栏在"下单前"，且用的是同一个不可靠模型。**
护栏失效 = 人死。→ **护栏必须前置**：目标格 / 落脚点 / 居住点 / 工位用**同一把"可呼吸"尺子**；
  且执行后要**复核**（"已下令" ≠ "已生效"）。

## 3. 新架构：五层 + 活命链

    ┌─ 感知 sense ────────────────────────────────────────────┐
    │ 人（位置/呼吸/压力/所处格元素） 气体 资源 建筑 电力 作物 │
    └───────────────────────────┬─────────────────────────────┘
                                ↓
    ┌─ 世界模型 world（自建，不信官方局部）──────────────────┐
    │ 全局可达图（梯子链 + ONI 移动规则）  气室图  危险区      │
    │ 资源分布（距离/方位/上方还是下方）  地表路径             │
    └───────────────────────────┬─────────────────────────────┘
                                ↓
    ┌─ 规划 planner（新）────────┴────────────────────────────┐
    │ 开局：地形特征 → 策略族 → 生成依赖图 + 判据 + 动作       │
    │ 途中：事件驱动重规划（人口下降 / 氧气告急 / 节点失败）    │
    └───────────────────────────┬─────────────────────────────┘
                                ↓
    ┌─ 调度 priority（扩）────────┴──────────────────────────┐
    │ 实时状态 → 指令（活命 > 空气 > 卫生 > 食物 > 供电 > 发展）│
    └───────────────────────────┬─────────────────────────────┘
                                ↓
    ┌─ 执行 autoact/exec ───────┴────────────────────────────┐
    │ 语义动作：surface / element:X / material / oxygen / power │
    │          research / forage / farm / mop_dirty / expand    │
    └───────────────────────────┬─────────────────────────────┘
                                ↓
    ┌─ 安全 safety（新，前置 + 复核）─────────────────────────┐
    │ 前置：工位/落脚点/居住点必须可呼吸；不派活进毒气区      │
    │       有人倒地 → 停工（保命节点除外）                   │
    │ 复核：区分「已下令」与「已生效」；失败要显式报告        │
    └─────────────────────────────────────────────────────────┘

## 4. 通用性从哪来：**地形特征 → 策略族**（不是 AI 判断，是规则匹配）

**关键认知：ONI 的死因只有 5 类** —— 窒息、污染（脏水/毒气）、饥饿、脱水、过热。
所以通用助手不需要"创造力"，只需要**把这 5 类变成可检测、可拦截的规则**。

**策略族（开局特征匹配 → 生成不同的依赖图）**

| 特征 | 策略族 | 第一目标 | 硬约束 |
|---|---|---|---|
| 可站区域只有 1 行高 | **憋死型** | 垂直竖井 + 梯子 → 开阔气室 | 禁止向下深挖（下方可能是 CO₂/水袋） |
| 到地表 ≤ 12 格 | **近地表型** | 打通地表 | 优先向上，禁止扩张 |
| 附近有氧石 | **富氧型** | 产氧器（氧石） | 产氧器要落在富氧格 |
| 附近有煤 + 铜 | **富矿型** | 供电链（砖→发电机→接线） | 发电机要铜且要人在里面待 → 选富氧格 |
| 开局无食物植物 | **无植物型** | 研究 → 土培砖 → 农业站 | 食物必须靠种植（收割是应急） |
| 下方有大水袋 | **水袋型** | 只向上 | 深挖 = 淹死 |

**通用助手 = 特征匹配器 + 策略族库 + 事件重规划。**
换一颗星球、换一种开局 → 匹配到不同策略族 → 生成不同依赖图。**这就是"面对不同情况"。**

## 5. "每局一个规划 + 每周期实时调整"——对，但两者都要规则化

* **每局规划**（开局一次 + 事件触发重规划）：生成**目标序列 + 判据 + 动作**，不是坐标清单。
  坐标由世界模型运行时算（这正是 AGENTS.md §13.11 早就写下的原则，本局只是把它落到了实处）。
* **每周期调整**（已有 priority.rs）：实时状态 → 指令，能抢占静态计划。
  本局教训：**调度器必须把"人当下在哪、能不能到那"当输入**，否则会把人送进毒气区。

**重规划触发事件**（本局全部踩到）：
人口下降 / 氧气续航 < 阈值 / 某节点连续失败 / 气室结构改变（打通或封闭）/ 资源耗尽。

## 8. 已落地验证（2026-11-22 11:29）

**新存档「陨石坑 / 埃莉星」上跑通完整闭环**（与上一局完全不同的星球与开局）：

```
oni plan-auto  →  策略族：先建材型（开局零建材）
                →  A1 = 采建材（梯子/砖/厕所/床全都造不了 → 先横向采）
代理第 1 轮      →  「铺梯子缺建材 → 改走横向挖掘」（降级正确）
代理第 2 轮      →  横向挖到 500kg 砂岩
代理第 3 轮      →  「竖井：先在 (125,187) 铺梯子，再挖 (125,189) 的头顶」
```

**这就是「不接 AI 在线管控也能玩」的最小闭环**：
开局特征 → 策略族 → 依赖图 → 语义动作 → 运行时降级 → 逐轮推进。

### 通用性证据

| 维度 | 小星局（特拉星） | 陨石坑局（埃莉星） |
|---|---|---|
| 存档指纹 | f9deadc6bcc3006c | 7fc8e406e822936d（互不污染 ✅） |
| 特征 | 1 格高走廊 + 有建材 | 1 格高走廊 + **零建材** + 氢气/氯气 |
| 策略族 | 憋死型 | **先建材型**（规则自动区分 ✅） |
| 第一目标 | 开竖井 | 采建材 → 再开竖井 |

### 仍然欠账（诚实清单）

* S1 未完成：**全局可达图**仍是「网格BFS ∩ 官方窗口」的混合体，
  官方 samples 的稀疏性仍会影响少数判定（已用网格 BFS 兜住，但不够纯）。
* S3 只做了一半：护栏前置做了（工位/落脚点/居住点同尺子），
  **执行后复核**（人真的到新位置了吗）还没有自动化验证。
* S5 未做：事件驱动重规划只有 should_replan() 的判定函数，尚未接进 agent 主循环。
* 策略族目前 6 个，覆盖常见开局；极端局（开局就有大量水/毒气）仍靠硬规则兜底。

## 9. 一句话

> **把「这一局怎么玩」从人的临场判断，变成「地形特征 → 策略族 → 依赖图」的规则函数；
> 把「人会不会死」从代理的乐观假设，变成世界模型里可验证的事实。**

剩下的工作不是"更聪明"，而是"更严谨"：
每个"我以为"都要换成"游戏说的"，每个"看起来安全"都要换成"可验证安全"。

### 仍然欠账

* **长竖井的梯子链**仍是瓶颈："目标列走不通"时只能横向挖，代理不会自己铺一条长梯子链。
* 事件重规划目前只接了**人口下降 / 氧气告急**两个触发；"节点连续失败"还没接进主循环。
* 全局可达图是"网格BFS ∪ 官方窗口"的混合体，官方 samples 的稀疏性仍影响少数判定。
* 本局资源分布印证了"上下分层"策略：**铁矿在地表附近（向上挖 ✓）、
  铜/煤/藻类在下方 20+ 格（深挖危险 ✗）** → 通用助手必须自己会做这种"方位取舍"。
