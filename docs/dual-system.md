# 快慢双系统架构

> 分工：**AI 要不断参与规划、处理问题；AI 是慢系统，代理是快系统。**
> 本文是这一分工的落地规范。
>
> **本文档描述的状态机以 [`docs/FAST_SLOW_CONTRACT.md`](FAST_SLOW_CONTRACT.md) 为唯一权威。**

---

## 1. 为什么必须是双系统

《缺氧》的对局是一个**开放世界 + 长时程 + 不可逆死亡**的问题：

* **快问题**（每 10 秒都要答）：现在最危险的是什么？这一轮该下什么单？
  → 必须由程序做（人不可能每 10 秒介入）。
* **慢问题**（每几分钟/每个关键节点）：这一局的战略是什么？目标是哪个？
  遇到"规则解不开"怎么办？跨局的教训能不能泛化？
  → 必须由 **AI** 做（需要理解语义、权衡、跨局泛化）。

把两者混在一起的两种失败模式：

| 错误 | 症状 |
|---|---|
| **只有快系统**（AI 退场） | 规则解不开时无限重试/空转；没人做大判断 |
| **只有慢系统**（AI 每轮指挥） | 回合太慢、烧周期；细节做不了 |

## 2. 分工表

| | 慢系统（AI / 主 agent） | 快系统（代理 / 守护进程） |
|---|---|---|
| **节奏** | 几秒~几分钟一次；开局一次、每次 escalation 一次 | 每 10 秒一轮 |
| **视野** | 全局：态势卡 + scout + 全图 + 跨局经验 | 局部：当前局面快照 + 本轮目标 |
| **产物** | plan.json（战略层）、代码、AGENTS.md 规则、records/* | 工单（挖/建/梯/砖/接线/收割）、选点、材料选择 |
| **决策权** | 目标顺序、换不换主线、什么时候放弃当前方案 | 怎么落地这一轮（选哪格、选什么材料、局部降级） |
| **遇到卡点** | —— | **escalation：喊人 + 暂缓该节点（世界继续跑）** |
| **世界暂停** | 不直接暂停世界（只有 `oni hold` 是用户的停止信号） | 自主决定运行/暂停；`hold` 与紧急态占空比除外 |
| **不许做** | 替代理做每轮执行 | 自己做跨周期战略判断 |

**不变式**：*慢系统不替快系统干活，快系统不替慢系统做决定。*

## 3. 交接协议

### 3.1 快 → 慢：escalation（喊人）

触发条件（**都是"规则解不开"**的情况，不是"再试一次能好"）：

| Kind | 触发 | 例子 |
|---|---|---|
| NodeFailing | 保命节点连续失败 | 产氧节点连撞 N 次（材料/空间解不了） |
| StrategyMismatch | 连续找不到建造落点 | 1 格高走廊放不下 2×3 厕所 → 布局决策 |
| NoFeasibleTarget | 语义目标找不到任何可行解 | 自举找不到任何可挖材料 |
| Deadlock | 依赖图没有可执行节点 | requires 指向不存在的节点 |
| NoProgress | 连续多轮零进展 | — |
| UnknownHazard | 未识别的危险模式 | 多人同时倒地 |

**升级之后不许继续重试该节点。**
行为：升级上报 + **暂缓该节点**（`mark_node_deferred`：下一轮不再选它）→ 等慢系统给新方向。
约束：保命节点"失败就重置计数 → 下一轮再试"是无休止重试，空耗周期。

**世界继续跑**：已有工单照做、膀胱/呼吸照常演化，快系统保命层照常执行。
不因慢系统而冻结世界（契约 §2）。

产物：
* ~/.oni-agent/saves/<指纹>/escalations/pending.json（待处理，按存档隔离）
* ~/.oni-agent/saves/<指纹>/escalations/history.jsonl（历史）
* 代理日志里一行 🆘 显眼标记。

### 3.2 慢 → 快：改计划

慢系统处理完，用 `oni escalations ack <id>` 告诉快系统"我处理了，继续"；
`oni resolve <id>` 是统一收口（escalation ack + bus resolve 二合一）。
同时把新战略写回 plan.json（走 saveswitch::write_plan，指纹永远正确）。

### 3.3 慢系统的工具箱

| 命令 | 用途 |
|---|---|
| oni observe | 全局态势卡（人/气/资源/建筑/电力/趋势） |
| oni scout | 资源分布侦察（距离 + **在下方还是上方**） |
| oni graph --full | 气室图 + 到地表路径（几何最短路 + 未探索标记） |
| oni plan-llm | 手动触发 LLM 开局规划（采事实 → 生成 → 校验 → 落盘） |
| oni plan-reset | 重开规划：清旧计划 + 同步生成新开局战略 |
| oni plan-check | 依赖图体检（假 done / 判据复核） |
| oni escalations | **快系统喊上来的请求**（慢系统工作台） |
| oni note / oni promote | 局内笔记 / 上提到通用记忆 |
| oni state | 存档身份与局内缓存目录（跨局隔离检查） |

## 4. 开局规划的定位（LLM 生成，无本地兜底）

机制（`crates/oni-engine/src/opening.rs`）：

    快系统：采本局事实 → 写 opening_brief.json（侦察 + 结构化 facts）
    慢系统 LLM：依据 brief 生成节点图 → opening::validate_plan 强校验 → 落盘
    落盘：author=ai, locked=true（此后机械规划永不覆盖）

三条硬规则：

1. **不设机械规划器与模板 playbook**：代码里没有独立的规划器模块，CLI 也没有对应子命令。
   约束：把某张地图的开局经验固化成模板，换地图就不适用。
2. **无本地兜底**：LLM 失败或校验不过 → 本轮没有战略计划（plan 保持空占位 `author=pending_llm`）
   → 冷却 **10 分钟**（`opening_state.json` 的 `last_fail_ts`，代码值 600s）后重试。
   **没有"模板基线"可执行**；快系统的保命反射弧照常跑，它本来就不依赖 plan。
3. **通用性来自 prompt**：prompt 只放跨局通用原则（厕所前置 / 材料先行 / 换气判据用真实可达上界 /
   缺料自举 / 造出来≠在运转 / 产氧需电 / 研究站解锁高级产氧）+ **本局事实**；
   节点结构由 LLM 依事实决定（水世界→藻类箱/电解器，陆地→氧石扩散器/挖掘换气）。

**校验拦幻觉**（`opening::validate_plan`）：判据 kind 白名单 / 判据不得重复 / requires-unlocks 引用存在 /
不得写死坐标 / 五条生命线必须覆盖（卫生·氧气·食物·床位·电力）/ 产氧节点的 requires 必须含供电节点（先电后氧）。

**AI 保留的权力**：目标顺序、换不换主线、放弃什么、风险取舍。
开局只是这一局的第一张节点图，之后每一步战略仍在慢系统手里。

## 5. 一次升级的标准往返

    快系统：目标连续失败达阈值 → 🆘 升级上报（并暂缓该节点）
    慢系统：读 escalations → 诊断 → 决策（改主线 / 亲自下精确工单 / 改 plan）→ ack
    快系统：沿新主线推进

慢系统可做**规则解不开的路径选优**：全图最短路只是几何参考，慢系统核对局部地形后
可以改走更短的路径（例如顺路取到产氧原料的竖井）。

## 7. 四条通道（完整闭环）

    ┌─────────────┐   指令    ┌──────────────┐  plan.json  ┌──────────────┐
    │   用户      │ ────────► │  慢系统(AI)  │ ──────────► │ 快系统(代理) │
    │ (可随时下达) │ ◄──────── │  巡检/决策    │ ◄───────── │  感知/执行   │
    └─────────────┘   回执    └──────┬───────┘  工单      └──────┬───────┘
                                       ▲                          │
                                       │  escalations（喊人）      │
                                       └──────────────────────────┘
                     audit（主动巡检发现的问题）也进慢系统

| # | 通道 | 载体 | 谁发起 | 谁消费 |
|---|---|---|---|---|
| 1 | 用户 → 慢系统 | oni command add "<指令>" 队列（按存档隔离） | 用户 | 慢系统翻译成计划/工单/代码 |
| 2 | 慢系统 → 快系统 | plan.json（战略层）+ 直接下精确工单 | 慢系统 | 快系统执行 |
| 3 | 快系统 → 慢系统 | escalations/pending.json（喊人 + 暂缓该节点） | 快系统 | 慢系统决策 → ack |
| 4 | 慢系统 → 慢系统 | oni audit（**主动巡检**） | 慢系统 | 慢系统（不等故障） |

### 7.1 通道 1：用户指令

    oni command add "优先建 3 个厕所，全部建在富氧区；别再往下挖了"
    # 慢系统读到后：
    #   ① 翻译成计划修改（厕所节点提到最前、判据 toilets>=3）
    #   ② 翻译成代码修改（「别再往下挖」→ 自举时下方材料直接排除）
    #   ③ 回执
    oni command done <id> "已落实：① … ② … ③ …"

**指令要落到「计划 + 代码」两处**：只改计划会被代理的局部逻辑绕开；
只改代码则没有全局意图。"别再往下挖"这种**硬约束**必须进代码。

### 7.2 通道 4：主动巡检

`oni audit` 跑一遍体检清单，输出问题 + 建议：

| 检查码 | 触发 | 建议动作 |
|---|---|---|
| pop.drop | 人口下降 | 查死因 + 回滚存档 |
| hygiene.no_toilet | 膀胱>80% 且厕所<人口 | 优先建厕所（富氧区+地板砖） |
| sleep.no_bed | 床位<人口 | 建床 |
| air.co2_ratio | O₂/(O₂+CO₂) < 75% | 通地表/拓宽通风；居住区上移 |
| oxygen.stalled | 有产氧件但空气比仍低 | 查三件套：投料/接线/位置 |
| power.not_connected | 有发电机但 consumerUsedWatts=0 | 接线到耗电建筑 |
| food.runway | 食物 < 3 周期 | 收割应急 + 建农场 |
| hygiene.polluted_air | 污染氧 > 40kg | 区域擦洗 + 居住区搬离 |

与 escalation 的区别：**audit 是慢系统主动跑（无故障也能发现问题），
escalate 是快系统被动喊（遇到解不开的情况）**。两者产出统一交给慢系统决策。

## 8. 暂停与停手语义规范（契约 §5 的落地）

状态收敛为 **4 种**，**没有第 5 种**。

### 8.1 状态编码（契约 §5）

| 状态 | 存储 | 生命周期 | 谁能改 |
|---|---|---|---|
| AI 开关 | hold 文件 + control owner=hold | 跨重启 | 用户（Web 总开关）/ 主 agent |
| 紧急占空比 | `Agent.danger_cycle` + `window_until` | 本进程 | 快系统（按红线自动） |
| 施工窗口 | `window_until` + `auto_rhythm` | 本进程 | 快系统（到期/续窗） |
| 本轮急症跳过扩张 | 局部变量 | **仅本轮** | 快系统（按 directive） |

**没有第五种状态**：任何"因为慢系统所以停手"的实现都是错误实现。
急症只跳扩张类 goal（expand/scout/surface/open-chamber）；保命/续航类 goal（material/oxygen/
element:X/建厕所/制氧/进食）任何时候都照常执行。
单轮跳过用**局部布尔**，生命周期仅本轮，不跨轮、不共享。

### 8.2 允许暂停的情形（契约 §2 不变量 1）

| 情形 | 世界状态 | 解除 |
|---|---|---|
| `oni hold`（用户关 AI 总开关 / 主 agent 改代码） | ⏸ 冻结，代理只观察 | 只有 `oni release`（或主 agent 清 hold 标记） |
| 紧急态占空比（有人倒地 / 呼吸红线） | 冻 20s → 跑 120s | 环境改善后自动 |
| 施工窗口正常到期 | 冻 20s 后自持续窗（有活续窗 / 空闲冻回） | 自动 |
| 本轮动作失败但慢系统仍有待办 | 冻 20s 后自持续窗重试，由熔断计数驱动换目标 | 自动 |
| 动作失败且慢系统彻底无待办 | 冻回等人工介入（**终态，不自持**） | 人工 |

**"等慢系统"不是暂停理由**：慢系统离线不该让殖民地饿死——快系统的保命反射弧本来就不依赖慢系统。
判定"世界在不在跑"必须用**实时真值**（`isPaused` / `gameSpeed<=0` / 实时复核），
不能只信批量采集的快照 `paused`（契约 §2 不变量 1）。

### 8.3 暂停所有权（control.json owner 表）

落盘位置：`saves/<fp>/control.json`（owner + reason + since），路径用 `last_seen()` 拼，
保证 CLI 与守护进程两个进程看到同一个 owner。

| owner | 谁在写 | 代理怎么处理 |
|---|---|---|
| `hold` | `oni hold` / Web「停止 AI」 | 早退：冻世界 + 代理只观察，等 `oni release` |
| `agent` | 代理自己（窗口到期 / 空闲停机 / 自持冻结） | 可恢复 |
| `user` | 手动暂停 / hook | **可恢复**（AI 开启时代理自主恢复，长线任务不被打断） |
| `escalation` | 等慢系统 | **可恢复** |
| `none` | 没人暂停 | 正常运行 |

**统一恢复**（`crates/oni-engine/src/agent.rs` 的"统一恢复"分支）：AI 开启时，
除 `hold` 外的所有 owner（agent/none/user/escalation）一律视为可恢复 → 清 owner +
`game_control resume` + 开施工窗口。用户不需要单独暂停游戏，代理也不会把长线任务
（竖井、研究）冻在半路。
读不到 / 损坏的 control.json → 视为 `Owner::None`（**不臆造暂停**）。
`oni window <秒>` = 用户显式授权代理恢复：清 owner → 开窗。

## 9. 「代理卡住」到底涉及哪些情况（单一真相来源）

全部收在 `crates/oni-engine/src/stuck.rs` 的 `detect()` 里 —— **每轮跑一遍，产出统一清单**；
清单非空 → **升级慢系统 + 暂缓该节点**（世界继续跑，已有工单照做，保命动作照常）。

| # | 卡住类型 | 判据 | 后果（不处理会怎样） |
|---|---|---|---|
| 1 | **预检不过** | 找不到落点 / 支撑不实 / 落脚点不可达 / 占格被占 | 节点永远失败 → 空转烧周期 |
| 2 | **语义目标找不到** | surface / oxygen / element:X 都找不到可行解 | 代理不知道往哪走 → 反复报同一错 |
| 3 | **材料缺失** | 缺建材且自举也找不到可挖材料 | 每轮尝试注定失败的建造 |
| 4 | **死工单** | 地图上有 dig 标记，但无待办 + 全员空闲 | ⚠️ mod 的 dig 标记不进 pendingOrders → 代理误判"空闲"→ 冻回 → **工单永不执行** |
| 5 | **节点反复失败** | 动作连续失败 ≥ N 次 | 无限重试同一个方案 |
| 6 | **依赖图死锁** | 没有可执行节点（requires 指向不存在的节点 / 全被熔断） | 刷屏"依赖图里没有可执行目标" |
| 7 | **复制人倒地** | 差事 = 失去行动能力 | 不执行任何差事；**且搬不动**（move_to 要寻路） |
| 8 | **复制人在毒气格** | 所在格不可呼吸 且 呼吸 < 60（且不在自救差事中） | 呼吸一路掉到 0 → 倒地 → 死 |
| 9 | **人口下降** | 本轮人数 < 上轮 | 有人没了（红线） |
| 10 | **长期零进展** | 连续 ≥ 3 轮指纹不变 | 方案本身走不通（该换，而不是加轮次） |

- **第 4 条**：mod 的挖掘标记**不进** `pendingOrders`，所以"有工单在位"和"有活可干"
  在官方数据里**无法区分**。只能用"地图标记数 > 0 且无待办且全员空闲"这个组合反推死工单。
- **第 8 条的阈值**：卡住检测取 60（调度抢占另有一套阈值，见 skill `oni-colony-ops` §7），
  并排除正在自救的差事（休息/睡觉/擦洗/寻找安全区/恢复呼吸）
  ——复制人在 CO₂ 主导的格子里睡觉是常态，单点判"呼吸偏低"会把睡着的人误判成危险 → 误冻结世界。
- **第 7 条的连带事实**：倒地的复制人**搬不动** →
  救援机制对"倒地"实际无效 → 必须在**事前**避免（居住区远离毒气 + 富氧区有床）。
- **第 10 条的处置**（契约 §4.5）：执行层循环不靠穷举挡住，而是靠**指纹**（`kind@x,y`）检测：
  同一指纹连续出现 ≥3 次 → 上报慢系统（指纹 / 次数 / 失败类别 / 现场事实）+ **暂缓该节点**打断循环；
  指纹中断（换动作）→ 计数归零。
