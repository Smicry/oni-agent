# oni-agent 架构 v3 —— LLM 驾驶 / 滚动窗口 / 安全壳

> 状态：设计定稿。本文是架构层的唯一权威；
> 快慢分工细则见 [`FAST_SLOW_CONTRACT.md`](FAST_SLOW_CONTRACT.md)，工程规则见 [`AGENTS.md`](../AGENTS.md)。

## 0. 一句话

**像自动驾驶一样分层：LLM 是大脑（理解 + 决策 + 长尾），滚动窗口是导航（每轮重算的短视轨迹），
安全壳是 AEB（硬编码红线，不经大脑），执行器是线控底盘（忠实执行，如实回报）。
层间只传结构化数据，不传自然语言；每层只做自己那一层的事。**

## 1. 设计约束：不用 if-else 重新理解 LLM 已理解的世界

约束：快系统里不出现以下几类规则代码——它们各自"局部正确"，合起来却让系统失去方向：
- 用字符串匹配（`tag.contains("…")`）翻译 LLM 的意图；
- 硬编码阈值与硬编码保命动作散落在主循环；
- 用一批状态 bool 表达运行状态（运行状态以 `RunState` 为单一真相源，bool 只作派生来源）。

**不再用 if-else 规则重新理解 LLM 已经理解过的世界**：意图由 LLM 以结构化数据给出（§2.1），
硬编码只允许出现在安全壳（§2.3），运行状态收敛为一个状态机（§5）。

## 2. 三层架构

```
┌──────────────────────────────────────────────────────────────┐
│  L  慢系统 = LLM 大脑                                          │
│     职责：理解世界 · 决定去哪 · 处理一切没见过的情况             │
│     输出：Intent（结构化 JSON，枚举字段，不含坐标）             │
│     频率：事件驱动（世界变了才叫）+ 60s 低频心跳                │
└──────────────────────────┬───────────────────────────────────┘
                           │ Intent{verb, object, constraint, horizon, fallback}
┌──────────────────────────▼───────────────────────────────────┐
│  P  规划器 = 导航（MPC 式滚动窗口）                            │
│     职责：把 Intent 变成未来 3~5 步的可执行序列                 │
│     输出：Window = [Step{action, pre, post}, …]               │
│     频率：每轮重算，只执行第一步；第二步以后是"意图"不是"承诺"  │
└──────────────────────────┬───────────────────────────────────┘
                           │ Step（一步，带前置/后置条件）
┌──────────────────────────▼───────────────────────────────────┐
│  F  快系统 = 安全壳 + 执行器                                   │
│     安全壳：红线硬约束（呼吸<35 / 膀胱爆无厕所 / 倒地）        │
│              → 4 个封闭反射，允许硬编码，每个有回归测试         │
│     执行器：Step → 预检 → 下单 → **如实回报** ok/fail + 原因    │
│     不做：不判世界在不在跑（问传感器）、不判目标是谁（Step 写着）、│
│           不做节点匹配（没有"匹配"这回事）                     │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 Intent：LLM 直接产出结构化意图

```json
{
  "verb": "ensure",
  "object": "sanitation",
  "constraint": { "count_gte": 3, "within_cycles": 2 },
  "why": "膀胱 100%，厕所 0",
  "fallback": ["dig_space_first", "outhouse_if_toilet_locked"]
}
```

- `object` 是**稳定枚举**：`sanitation / oxygen / food / shelter / power / expand / research / rescue`
- LLM 从枚举里选，`why` 自由文本给人看，`fallback` 是 LLM 预判的备选路径
- **没有"节点匹配"**：快系统不做 `find(tag.contains("厕所"))`；意图到动作的翻译在 LLM 侧完成

### 2.2 滚动窗口：全局 DAG 有害，目标函数才有用

ONI 是**部分可观察 + 随机**的世界（挖开才知道后面是 CO₂ 还是水）。静态 7 节点 DAG 把
"现在的判断"固化成"未来的约束"，世界一变就成枷锁。

**保留的是目标函数 + 约束（交通规则，很少变），不是路线（每轮重算）：**

```yaml
objectives:
  - survive: { priority: 0, hard: true }   # 无人死亡/窒息
  - sustain: { priority: 1 }               # 氧气/食物/卫生续航 > N 周期
  - grow:    { priority: 2 }               # 人口/可达区/研究
constraints:
  - never_dig_below_reachable
  - never_build_in_unbreathable
```

### 2.3 安全壳：唯一允许硬编码的地方

红线动作集是**封闭的**：`vital_reflex` 把保命动作（建厕所 / 救援 / 产氧·换气 / 采集食物）
翻译成四个语义目标 `toilet / mop_dirty / oxygen / forage`（`reflex.rs`），
由 autoact 运行时探测 prefab 与落点；供电/扩张属于战略层，不在反射集内。
每个反射都有回归测试；不做"匹配"，只做"触发 → 反射"。
世界状态判定**只问传感器**（`isPaused` / `gameSpeed`），`colony/status` 走 1s TTL。

### 2.4 执行器：只执行与回报

输入一个 Step，输出 `ExecResult{ok, fail_kind, detail}`。
`ok` 由 `aggregate_ok` 真实汇总，零进展 = 失败。
**不做任何判断**——"该不该做"由 P 决定，"目标是谁"由 Step 写明。

## 3. 四条原则

1. **感知不推断**：快系统只读传感器真值，不缓存、不快照、不推断。
   违反示例：用缓存的过期快照判"世界在跑"。
2. **回报不美化**：`ok` 必须来自真实结果，禁止默认 true；零进展算失败。
   违反示例：`execute()` 末尾硬编码 `ok: true`。
3. **意图不解析**：LLM 给结构化 Intent，快系统零字符串匹配。
   违反示例：用 `tag.contains("厕所")` 翻译 LLM 的意图。
4. **规则只放红线**：硬编码只允许在安全壳（人不能死），其余一律 LLM。
   违反示例：恢复条件散落在多个分支，保命节点在恢复与冻回之间乒乓。

## 4. LLM 输出的契约层

约束：LLM 输出与代码 schema 之间必须有契约层——字段写法不同（`{key,n}` vs `{element,kg}`）
不能导致判据永不成立。

- 判据格式用 **JSON Schema 定义一次**，prompt 的例子**从 schema 自动生成**（手写例子 = 手写 corner case）
- 代码用 schema 校验；字段别名（`key/element`、`n/kg`）在契约层适配（`crit_num / crit_str`）
- LLM 输出带 `schema_version`，不兼容时拒绝而不是猜

## 5. 状态机收敛

- 运行状态为 **3 态**：`Running / PausedByHold / PausedByDanger`（`RunState`，`agent.rs`）。
- 状态转移由一个纯函数给出（`derive_run_state`），是观测的单一真相源。
- 各处状态 bool 写入点保留为派生来源。

hold（用户总开关）是唯一受保护的停止；其它一切暂停由代理自主恢复。

## 6. 各层落地形态

- **安全壳** `reflex.rs`：`world_paused`（只问传感器）+ `vital_reflex`（封闭反射集）；单测覆盖反射集合封闭性。
- **滚动窗口** `window.rs`：horizon-3；窗口过期（空 / 全部完成 / 全部 blocked·deferred / 跨 ≥2 周期）即 LLM 重算，
  注入上一窗口执行结果作反馈闭环；单测覆盖过期判定与 W1 可执行约束。
- **状态机**：`RunState` 三态作**观测单一真相源**（`derive_run_state` 纯函数 + 日志打印 `state=`）；
  多处 bool 写入点保留为派生来源；单测覆盖派生优先级。
- **Intent 枚举**（verb/object/constraint）的完整落地在慢系统 prompt 侧，当前以 `goal` 枚举 + 滚动窗口过渡。
- MCP 层（`oni-mcp`）与执行层（`exec.rs` / `autoact.rs`）保持现状，不属于本架构的改动对象。

## 7. 直接回答两个问题

**全局规划有用吗？** 对部分可观察世界，静态全局 DAG **有害**。LLM 的价值不在"一次规划对"，
而在"每次都能按新事实重规划"——所以让它**高频短视**（滚动窗口），而不是**低频远见**（长链 DAG）。

**和自动驾驶一样吗？** 是。LLM = 大脑，滚动窗口 = 导航，安全壳 = AEB/ESC，执行器 = 线控底盘。
约束：自动驾驶从不让 AEB 去"理解"行人，也不让导航去"匹配"车道线的文字描述。
