# 地图图结构设计（MapGraph）

> 代码位置：`crates/oni-world/src/graph.rs`，CLI：`oni graph`。
> 本文解释"为什么是图"、"图怎么定义"、"能回答什么问题"。

## 1. 为什么线性网格不够

旧世界模型是一张 `HashMap<(x,y), Kind>` 网格，只能回答**局部几何问题**：
- "这一格能不能挖？"（预检）
- "复制人走得到这一格吗？"（BFS 可达域）

回答不了**全局结构问题**，而这些正是每次全灭的根源：
- "哪个气室的氧气快耗尽了？" —— 需要把气体按连通域分组算预算
- "从生活区到地表，最短要挖几格？" —— 需要对隔层建图求最短路
- "挖开哪一格能一次连通最多的气室？" —— 需要图的割点/度分析
- "氯气沉在哪个坑里？" —— 需要按气室统计危险气体

## 2. 图的定义

### 节点 = 气室（Chamber）
**4 邻接的开放格**（气体 / 液体 / 梯子 / 复制人）构成一个连通域。
选 4 邻接而非 8 邻接：气体只在正交方向扩散，斜角不算连通（与 ONI 气体模拟一致）。

每个气室的属性：

| 属性 | 来源 | 用途 |
|---|---|---|
| `cells` | Grid（viewport.md + 官方字形表 + 建筑索引） | 气室范围、挖掘目标 |
| `masses` | `oni://world/cell/{x}/{y}` 的 element/massKg（并行取） | 氧气/CO₂/氯气/资源统计 |
| `has_dupes` | `oni://dupes/todos` 的位置 | 标记当前生活区 |
| `touches_surface` | 气室内是否有格 ≥ maxY-2 | 无限空气源判定 |
| `breath_ratio()` | O₂/(O₂+CO₂) | 局部空气红线 |

### 边 = 实心隔层
两个气室之间若只隔 1~k 格实心岩，挖开即连通，边的代价 = k。
`route_to_surface()` 用 **0-1 BFS**（开放格代价 0，实心格代价 1）求生活区到地表的最短挖掘路径。

## 3. 能直接回答的问题（代理的查询接口）

| 查询 | 方法 | 战略价值 |
|---|---|---|
| 当前生活区氧气还能撑多久 | `dupe_chambers()[i].oxygen_cycles(n)` | 决定"先产氧还是先挖矿" |
| 哪些气室空气有毒 | `hazardous_chambers(0.55)` | 避开氯气坑 / CO₂ 沉底坑 |
| 到地表要挖几格 | `route_to_surface().dig_count` | 估算开拓成本，选竖井位置 |
| 哪个气室有矿 | `chamber.top_masses(3)` | 决定下一挖方向 |
| 危险气体在哪 | `chamber.hazards()` | 通风规划 |

## 4. 数据来源与真值层级（与项目全局一致）

1. 格子类别：`Grid::load` —— 官方 viewport.md + `/active/buildings/index.md` + 官方字形表（不靠渲染猜建筑）。
2. 气体质量：`oni://world/cell/{x}/{y}` 的 `element` / `massKg`（官方真值，不用渲染字形）。
3. 复制人位置：`oni://dupes/todos`（与 preflight 同源）。
4. 地表判定：viewport 上界 Y-2（ mod 的 Y 轴向上递增）。

## 4.5 全图模式（`oni graph --full`）—— 应对各种地图的关键

`viewport.md` 只覆盖**相机视野**（默认 65×41）。换一张大地图、或把相机移开，
"到地表要挖几格""哪个气室在憋 CO2"就会随相机位置漂移 —— **算出来的地图是错的**。

mod 提供 `/active/map/layers/layer_<y0>_<y1>.md`：**全宽 X=0~255，按 Y 每 32 行一层**，
逐层读即可拿到整张星体（12 层 = Y 0..383）。

```bash
oni graph --full          # 全图气室图
```

### 三个必须知道的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| **RLE 压缩** | 图层文件用 `?x5` 表示 5 个 `?`、`Ox3` 表示 3 个 `O` | `expand_row_tokens()` 展开；不解 RLE → **坐标全部错位**（整行只对上 1 列） |
| **未探索区（`?`）** | 全图大片区域是 `?`（游戏迷雾） | **不能当实心岩**。它是"代价未知的可挖空间"，寻路按代价 1 处理；当墙 → 永远找不到地表 |
| **地表不是地图顶部** | 全图顶部 Y=383 是太空，地表在 Y≈223 | 地表 = **有实心地形的最高层**（`surface_y`），不能取 `max_y` |

### 路径可信度标注

全图路径可能穿过未探索区 → 那部分是**推测**。`DigRoute.unknown_cells` 记录这类格数，
报告里显式标注：

```
地表线 Y=223（有实心地形的最高层）
到地表最短挖掘路径：需挖 18 格，路径 49 步
  ⚠ 路径有 2 格落在未探索区（推测，非事实）→ 只作开拓方向参考
```

### 取数预算

全图近 10 万格，**逐格 fetch 会把查询拖到几分钟**。只精确统计：
1. 含复制人的气室（生活区，空气预算直接决定生死）；
2. 面积最大的 12 个气室（`MAX_PRECISE_CHAMBERS`）。

其余气室只记格子数。全图查询实测 ~12 秒。

## 5. 已知限制（诚实标注）

- **氧耗速率是社区经验值**（60kg/人/周期 ≈ 0.1kg/s × 600s），非官方数值；只用于气室间的**相对比较**，不作生死判定。见 `docs/knowledge-base.md`。
- **续航按"封闭气室"假设**：实际挖通后会扩散，续航会变长；这不是 bug，是"不打通就只剩这么点时间"的保守估计。
- **挖掘路径是纯几何最短路**：未考虑官方可达域、保护区（打印舱/发电机）、梯子规则。它是"往哪个方向开拓"的参考，不能直接下单；具体挖掘仍要走 `preflight_dig`。
- 气室数是 viewport 可见范围（默认 65×41）内的，移动相机会改变图。
